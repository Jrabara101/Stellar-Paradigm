# React + Vite migration

The game is being moved from one big vanilla-JS file (`script.js`, ~4.3k
lines) to React + TypeScript + Vite, **in stages**. After each stage the app
is still playable and deployable, on the web and on Android.

## How it works during the port

```
index.html            Vite entry. Still holds the legacy markup for unported surfaces
                      (title, board, rack, stat bubbles) plus .rx-slot mount points for
                      React surfaces, and a #boot-cover for the first paint.
public/               Legacy runtime, served untouched at the same relative paths:
                      script.js, stellar.js, style.css, themes.css, wordbank.js,
                      scramble-board.*, qrcode.js, sw.js, icons/, fonts/ …
src/                  New React + TS code (bundled + hashed by Vite)
  main.tsx            Mounts React into #react-root, installs overrides, native init, SW
  App.tsx             Mounts every ported surface
  modals/             The 11 menu modals ported in Stage 2 (+ components/ChangelogModal.tsx)
  components/         Modal shell, PickerCard/PickerGrid (theme/chip/font/effect cards), Switch
  data/               changelog.ts, pickers.ts (generated by tools/extract-pickers.py)
  legacy/bridge.ts    Typed handle on window.game / window.stellarWallet + whenGameReady()
  legacy/useGame.ts   useGame() re-reads game state; act() runs a legacy action + re-renders
  legacy/overrides.ts Re-points ported game.* methods at React (per instance)
  legacy/prototype.ts Overrides the constructor itself calls (runLoadingScreen), patched
                      on TeakScrambleGame.prototype before DOMContentLoaded builds the game
  components/         HeaderMenu (☰), GuidePanels, VictoryScreen, LoadingScreen (Stage 3)
  store/ui.ts         Modal stack + per-modal dismiss handlers (Escape / backdrop / Android back)
  store/refresh.ts    Refresh requests for the leaderboard / credentials views
  store/header.ts     ☰ open state, guide/stat panel visibility, Scramble Board lazy-load
  store/victory.ts    Victory overlay content + victoryScreenProxy (stands in for the old element)
  store/loading.ts    Loading overlay start/finish (starts active, see "Startup" below)
  components/Modal.tsx Shared Motion modal: spring on desktop, sheet ≤520px dragged by its handle
  native/index.ts     Capacitor: back button, haptics, system bars, splash
```

**To port a surface:**
1. Build the component (`src/modals/` for a modal), using the legacy CSS class for the panel
   so all themes' `--teak-*` tokens keep working. Read state with `useGame()` and run legacy
   actions through `act(() => game.x())` so the UI re-renders.
2. Override its `game.openX/closeX` in `legacy/overrides.ts`, so every existing caller
   (inline `onclick`, the entrance sequence, other scripts) reaches React.
3. Delete its markup from `index.html`. Any legacy method still called that looks the old
   markup up by id must be null-safe (`getElementById(...)?.`) or overridden.
4. If it is a modal, add its id to `ModalId` in `store/ui.ts` and give `<Modal>` an
   `onDismiss` if closing has side effects. Escape and Android back then work automatically.

**Surfaces inside the legacy layout** (menu, guide panels) render with `createPortal` into an
empty `<div id="rx-…" class="rx-slot">` left in index.html (`display: contents`, so the legacy
flex/grid rules see the React children). Give React elements **different ids** from the ones
script.js writes to (e.g. `data-menu=` on menu items): the legacy writes then no-op instead of
fighting React's reconciliation.

**Elements script.js caches in its constructor** (`this.victoryScreen = getElementById(...)`)
are replaced after construction with a stand-in object (`victoryScreenProxy`) whose
`classList` drives a store.

**Startup.** The browser paints index.html before any script runs, and React renders before
DOMContentLoaded builds the game. `#boot-cover` (the loading background colour) is in that
first paint; the loading overlay starts active and removes it on mount. `main.tsx` commits
React's first render with `flushSync` so the overlay exists before the constructor runs.

Keep the `modal-backdrop active` classes on React backdrops: `wallet-guide.js` waits for
any `.modal-backdrop.active` to close before it auto-opens.

Asset paths referenced from `src/` (e.g. theme previews in `data/pickers.ts`) are found by
the `copy-legacy-assets` build step and the CI `.vercelignore` guard; both scan `src/` too.

## Stages

| Stage | Scope | Status |
|---|---|---|
| 1 | Vite + React + TS toolchain, legacy moved to `public/`, CI/CD/Vercel build `dist/`, Capacitor on `dist/`, native back/haptics/system bars/splash, Changelog modal ported | **done** |
| 2 | The other 11 modals: onboarding, category, theme / chip+font / tile-effect pickers, effects, audio, API settings, leaderboard, credentials, get-app. Guides + Level/Score/Streak bubbles hidden by default (reset once via `ws_ui_defaults_v2`) | **done** |
| 3 | ☰ header menu, How to Play / Hint Guide panels + pills, victory screen (Motion sequence: title → rows → count-up → buttons), loading screen; first paint never shows the bare board | **done** |
| 4 | Game engine to TS modules (scoring, word picking, daily, streaks, sound, particles); React board with layout-animated tiles instead of body-positioned absolute tiles; **Level/Score/Streak bubbles** (moved from Stage 3: script.js caches them and animates them from the scoring code, so they port with it) | next |
| 5 | `stellar.js` to a TS module; bundle stellar-sdk + wallets-kit from npm (no esm.sh, works offline in the APK); Scramble Board port | |
| 6 | Empty `public/` of legacy JS; service worker via Workbox; delete `www/` | |

## Commands

```bash
npm run dev            # Vite dev server (also reachable from a phone on the LAN)
npm run build          # typecheck + production build to dist/
npm run preview        # serve dist/
npm run android:sync   # build + cap sync android
npm run android:open   # open in Android Studio
npm run android:apk    # build + sync + gradlew assembleDebug
```

If Gradle fails with `resource layout/abc_… not found`, run `gradlew clean` first (stale build cache).

## Android notes

- Target SDK 36 (Android 16) is always edge-to-edge, and `@capacitor/status-bar`'s
  `backgroundColor`/`overlaysWebView` no longer have any effect. The app uses Capacitor 8's
  `SystemBars` (light icons), the injected `--safe-area-inset-*` variables, and a
  `.rx-statusbar-scrim` strip painted with the theme's `--teak-dark`.
- `launchAutoHide` is off, so the splash waits for the game shell. `initNative()` always
  hides it in a `finally`, plus a 6 s fallback.
- The service worker is web-only. Inside the APK every asset is already local.
